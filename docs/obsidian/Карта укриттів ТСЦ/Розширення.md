# Розширення — ТСЦ МВС Києва та області

Мета — одна карта для всіх ТСЦ Києва й Київської області: вибрати ТСЦ, потім маршрути, потім укриття поруч. Правила пілоту не змінюються: схеми лише офіційні, неоднозначні ділянки не публікуються, доступ до укриття не вигадується.

## Головна ідея: схеми за шаблоном URL

Файли схем №3246 лежать за адресами на кшталт `https://hsc.gov.ua/wp-content/uploads/2025/12/3246-12.jpg`, тобто `uploads/<рік>/<місяць>/<ТСЦ>-<маршрут>.jpg`. Можна підставляти номер ТСЦ і маршруту, доки не знайдемо всі файли.

Що з’ясовано 16.09 і що ускладнює перебір:

- **Статус зі скрипта нічого не каже.** `hsc.gov.ua` стоїть за Akamai: curl отримує `403 Access Denied` і на справжній `3246-12.jpg`, і на неіснуючий файл, і навіть на саму сторінку маршрутів. Отже, 403 — це не «не той файл», а блокування скрипта
- **Невідома тека.** `рік/місяць` — дата завантаження у WordPress, а не номер. Для кожного ТСЦ вона своя й може бути різною для окремих схем
- **Невідома кількість маршрутів.** Скільки маршрутів у ТСЦ, заздалегідь не відомо (у №3246 їх 12), а в назві можуть бути суфікси (`-1.jpg`, `-scaled.jpg`, `.png`)
- **Ризик бану.** Масовий перебір легко приймуть за атаку

## Порядок робіт

### 0. Перевірка в браузері (30 хв, до написання коду)

- [ ] У звичайному Chrome відкрити справжній `3246-12.jpg`, вигаданий `3246-99.jpg` і ту саму назву в іншому місяці. Записати коди відповіді
- [ ] Якщо неіснуючий файл дає 404, а справжній 200 — перебір можливий, але лише з контексту браузера (Playwright з профілем Chrome або claude-in-chrome), не curl
- [ ] Якщо все одно 403 — перебір не працює, лишаються кроки 1–2
- [ ] Перевірити в браузері `https://hsc.gov.ua/wp-json/wp/v2/media?search=3246&per_page=100`. Якщо WordPress REST відкритий, він дає точні URL усіх схем без перебору

### 1. Перелік ТСЦ

- [ ] З розділу «Маршрути» ГСЦ зібрати всі ТСЦ Києва й області: номер, адреса, посилання на сторінку. Зберегти як `research/tsc-list.json` із датою
- [ ] Кількість не вигадувати — лише те, що є на сайті

### 2. Точні URL схем (у порядку пріоритету)

1. Сторінка кожного ТСЦ, відкрита в браузері, — посилання на JPG, заголовки, дата наказу. Надійно й дає метадані
2. WordPress REST `media` (якщо відкритий) — повний список файлів
3. Перебір як запасний варіант, тільки з браузера:
   - маршрути 1…N; зупинка після 3 промахів поспіль
   - місяці спершу ті, що біля дати наказу, а не всі підряд
   - пауза 1–2 с між запитами, кеш знайденого, лог усіх спроб
4. Якщо нічого не працює — попросити файли, як з №3246, або звернутися до ГСЦ

Для кожної схеми зберігати: джерело, SHA-256, дату отримання, номер і дату наказу, категорії.

### 3. Дані й код

- [ ] Структура `data/<ТСЦ>/routes.geojson`, спільний `shelters.geojson` (або тайли за районами). Вибір ТСЦ у панелі, адреса виду `#3246`
- [ ] Укриття: уже є завантажувачі КОВА (область) і КМДА (Київ). Зону покриття рахувати від маршрутів кожного ТСЦ; для Києва можливі тисячі точок — кластеризація маркерів
- [ ] Дані громад (як brada) — лише де вони додають щось понад КОВА

### 4. Оцифрування — справжнє вузьке місце

Завантажити схеми просто. Складно звірити кожну лінію: у пілоті на 12 схем пішла ціла сесія, і 5 маршрутів досі не готові.

- [ ] Спершу один ТСЦ у Києві й один в області. Виміряти, скільки часу йде на маршрут
- [ ] Спробувати напівавтоматику: знайти сині лінії й червоні стрілки на растрі та прив’язати їх до доріг OSM. Людина лише звіряє результат
- [ ] Публікувати ТСЦ частинами: непідтверджені маршрути не показувати, як у пілоті

## Свідомо не робимо

- Сторонні траси, «популярні маршрути» з YouTube чи автошкіл
- Живі запити з браузера відвідувача до КМДА чи КОВА — тільки збережені знімки
- Масовий перебір без паузи й без перевірки з кроку 0
